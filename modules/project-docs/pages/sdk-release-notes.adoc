== {name-sdk} 1.1 Releases

Version {sdk_dot_minor} of the {name-sdk} implements the {sdk_api} xref:compatibility.adoc#api-version[SDK API].
See the xref:compatibility.adoc#couchbase-feature-availability-matrix[compatibility pages] for more information on feature compatibility with different versions of Couchbase Server.

We always recommend using the latest version of the SDK -- it contains all of the latest security patches and support for new and upcoming features.
All patch releases for each dot minor release should be API compatible, and safe to upgrade; any changes to expected behavior are noted in the release notes that follow.

Binary compatibility is not guaranteed for any {name-sdk} release, and you should rebuild your application when changing the SDK.

Version 1.1.1 is a maintenance release for the Rust SDK 1.1.

https://docs.rs/couchbase/1.1.1/couchbase/[API Documentation]

* https://jira.issues.couchbase.com/browse/RSCBC-320[RSCBC-320]:

Fixed an issue where a cluster config received in a `NotMyVbucket` response did not have `$HOST` substituted with the hostname of the node that sent it.
* https://jira.issues.couchbase.com/browse/RSCBC-300[RSCBC-300]:
Fixed an issue where the first cluster config fetched during bootstrap did not have `$HOST` substituted with the hostname of the node that sent it.

Fixed an issue where IPv6 hostnames substituted for `$HOST` in a cluster config were wrapped in square brackets twice.

[v1.1.0]
=== Version 1.1.0 (7 October 2026)

Version 1.1.0 is the first release of the Rust SDK 1.1, implementing the {sdk_api} SDK API.
It adds reads from a specific replica, Score Fusion for hybrid Search, and log redaction.

https://docs.rs/couchbase/1.1.0/couchbase/[API Documentation]

==== New Features and Behavioral Changes

* https://jira.issues.couchbase.com/browse/RSCBC-302[RSCBC-302]:
Added `Collection::get_replica`, which reads a document from a specific replica, chosen with a `GetReplicaStrategy`.
For example, `GetReplicaStrategy::from_index(ReplicaIndex::First, None)` reads from the first replica.
* https://jira.issues.couchbase.com/browse/RSCBC-309[RSCBC-309]:
Added log redaction, enabled with `ClusterOptions::log_redaction(true)`.
When enabled, the SDK wraps sensitive values in its log output in tags, so that a tool such as https://docs.couchbase.com/server/current/cli/cbcli/cblogredaction.html[cblogredaction] can strip or hash them.
Redaction is process-wide, and applies to log messages only, not to tracing span fields or metric events.
* https://jira.issues.couchbase.com/browse/RSCBC-275[RSCBC-275]:
Added Cargo features for finer control over dependencies:
`logging-meter` (the `LoggingMeter`), `threshold-logging-tracer` (the `ThresholdLoggingTracer`), and `dns-srv` (DNS SRV bootstrap and `DnsOptions`, via `hickory-resolver`).
All three are enabled by default.
If you build with `default-features = false`, enable these features explicitly to keep using them.
* https://jira.issues.couchbase.com/browse/RSCBC-285[RSCBC-285]:
Field names passed to `create_index` are no longer escaped by the SDK, so nested paths such as `d.firstName` now index the nested field.
Escape field names that need it yourself, using backticks.
* https://jira.issues.couchbase.com/browse/RSCBC-286[RSCBC-286]:
Query error code 2120 is now reported as an authentication failure.
* https://jira.issues.couchbase.com/browse/RSCBC-313[RSCBC-313]:
The crates now declare a minimum supported Rust version (`rust-version`) of `1.88`.

==== Fixed issues

* https://jira.issues.couchbase.com/browse/RSCBC-312[RSCBC-312]:
Fixed an issue where the query tracing span in query index management operations was not emitted under the `couchbase::tracing` target.
